# Автоматичні релізи AlexiHub

Після push у гілку `main` GitHub Actions автоматично:

1. читає нові коміти;
2. визначає тип нової версії;
3. додає запис на початок `community/releases.json`;
4. оновлює версію в налаштуваннях AlexiHub;
5. створює Git-тег на кшталт `v1.4.0`.

## Як називати коміти

```text
feat: додано пошук публічних серверів
fix(dm): виправлено завантаження профілю
perf: пришвидшено відкриття особистих повідомлень
security: закрито обхід перевірки прав
refactor: спрощено завантаження налаштувань
```

- `feat` підвищує `1.3.0` до `1.4.0`;
- `fix`, `perf`, `security` і `refactor` підвищують `1.3.0` до `1.3.1`;
- `feat!` або `BREAKING CHANGE` підвищує `1.3.0` до `2.0.0`;
- `docs`, `style`, `test`, `chore`, `ci` та `build` не потрапляють у список змін.

Якщо коміт названий `update` або `Add files via upload`, генератор перевірить
змінені файли та створить обережний загальний опис. Для точного тексту краще
використовувати формат вище.

За потреби реліз можна запустити вручну в GitHub:
`Actions` → `Auto changelog` → `Run workflow`.
